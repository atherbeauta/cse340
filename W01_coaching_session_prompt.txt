// Asynchronous function to retrieve and filter projects by category ID
const getProjectsByCategory = async (categoryId, allProjects) => {
    try {
        const filteredProjects = allProjects.filter(project => project.categoryId === categoryId);
        return filteredProjects;
    } catch (error) {
        console.error(`Error processing projects: ${error.message}`);
        return [];
    }
};
This snippet demonstrates modern JavaScript features. First, I used an arrow function assigned to a const identifier. The function is declared as async to handle data operations safely. Inside, I used the higher-order array method .filter(), which takes a predicate arrow function project => project.categoryId === categoryId to return only the items matching the given category ID. Finally, a try...catch block ensures proper error handling so the app does not crash if an exception occurs.

AI Coach: That's a very clean snippet, Athanase. Using .filter() with an arrow function makes the code concise and readable. Why did you choose to wrap this operation in a try...catch block even though .filter() is synchronous?

Athanase: I wrapped it in a try...catch block because, in a real backend environment, allProjects could potentially be undefined or null if a database query fails before reaching this function. The try...catch prevents unhandled runtime exceptions and allows the application to fail gracefully by returning an empty array.

In this template, I use output tag <%= title %> to safely render the dynamic page title passed from Express. For layout structure, I use the unescaped raw output tag <%- include('partials/header') %> and <%- include('partials/footer') %> to pull in modular EJS partials.

AI Coach: Perfect! Can you explain the difference between using <%= %> and <%- %> in EJS, and why you used <%- %> specifically for including partials?

Athanase: <%= %> escapes HTML characters before rendering them to protect against Cross-Site Scripting (XSS) attacks, making it safe for text data like user inputs or titles. On the other hand, <%- %> renders raw HTML without escaping it. We must use <%- %> for include() statements so Node.js renders the embedded HTML tags inside the partial file rather than printing raw HTML tags as plain text.
